# Объяснение практики 5

## Что сделано

Я собрал небольшую Go-программу syspulse, которая выводит версию и сведения
Linux из /proc. Затем упаковал её в .deb и опубликовал в Nexus APT. Workflow
проверяет установку через apt в новом Ubuntu-контейнере, запускает программу
и сохраняет .deb вместе с результатами как артефакт. Повторная публикация
той же версии разрешена политикой Nexus ALLOW.

## Возможные вопросы

**Что такое syspulse?** Учебная программа командной строки. Показывает версию,
версию Go, число CPU, uptime, load average и сведения о памяти Linux.

**Это показатели моего Mac?** Программа запускается в Linux-контейнере и читает
/proc Linux-окружения Docker. macOS такого /proc не предоставляет.

**Что такое .deb?** Пакет Debian/Ubuntu. Содержит архив файлов, архив метаданных
и служебный файл debian-binary. dpkg устанавливает его файлы по нужным путям.

**Где лежит исполняемый файл?** Внутри пакета по пути usr/bin/syspulse,
а после установки — /usr/bin/syspulse.

**Что находится в DEBIAN/control?** Название пакета, версия, архитектура,
сопровождающий и описание. Поле Version автоматически берётся из main.go.

**Что означает CGO_ENABLED=0?** Отключение использования C через cgo. Для этой
программы это позволяет получить статический Go-бинарник без динамической libc.

**Зачем GOOS=linux и GOARCH=amd64?** Они задают целевую ОС и архитектуру.
Сборка выполняется на Mac ARM64 через Go в Linux-контейнере, а результат
предназначен для Ubuntu amd64.

**Зачем Nexus?** Это сервер хранения и выдачи пакетов. APT получает от него
метаданные, узнаёт доступную версию и скачивает нужный .deb.

**Что значит hosted APT?** Репозиторий хранит наши загруженные пакеты.
Он не является прокси чужого репозитория.

**Что такое Release и InRelease?** Метаданные дистрибутива и их подписанный
вариант. Packages содержит сведения о пакетах, размерах и контрольных суммах.

**Чем загружен пакет?** curl выполняет HTTP POST содержимого .deb в корень
hosted APT-репозитория. Издатель проходит HTTP Basic Authentication.

**Где пароли?** В GitHub Secrets. Временный файл на runner имеет права 0600,
для curl создаётся временный netrc. По завершении они удаляются.

**Зачем отдельный deployer?** Чтобы pipeline мог публиковать только в syspulse,
не получая административных прав на весь Nexus.

**Что такое GPG и signed-by?** Nexus подписывает метаданные закрытым ключом.
Ubuntu проверяет подпись соответствующим публичным ключом, указанным в signed-by.
Закрытый ключ в репозиторий GitHub не добавляется.

**Чем apt отличается от dpkg?** dpkg непосредственно устанавливает .deb.
apt умеет работать с репозиториями и зависимостями и использует dpkg для установки.

**Что делает apt-get update?** Загружает сведения о доступных пакетах.
Саму программу эта команда ещё не устанавливает.

**Что делает apt-get install syspulse?** Выбирает пакет из метаданных,
скачивает его из Nexus и устанавливает.

**Почему проверка в новом контейнере?** Чтобы доказать, что пакет действительно
устанавливается из репозитория и не остался установленным после старого теста.

**Как доказывается установка из Nexus?** В новый контейнер монтируется только
публичный ключ. Локального .deb внутри нет. apt скачивает пакет по APT-источнику,
а скрипт проверяет версию, архитектуру и SHA256 установленного бинарника.

**Почему повторный запуск безопасен?** Nexus разрешает повторную публикацию
версии через writePolicy ALLOW. Каждый тест установки идёт в отдельном контейнере.
Concurrency не допускает одновременные публикации этой практики.

**Что является артефактом?** Загруженный в GitHub архив с .deb, бинарником,
метаданными сборки, журналом apt и результатом проверки.

**Что выполняется после ошибки?** Сбор диагностики и очистка временных файлов
имеют if: always(). Загрузка артефакта разрешена, если аудит файлов прошёл успешно.

## Порядок демонстрации

1. Открыть ветку release и .github/workflows/publish-deb.yml.
2. Показать два успешных запуска workflow.
3. В Nexus открыть репозиторий syspulse и пакет версии 1.2.0.
4. Показать dpkg metadata и файл dist/syspulse_1.2.0_amd64.deb.
5. Показать журнал установки из чистого Ubuntu и syspulse --version.
6. При необходимости запустить задачу проверки из VS Code.
